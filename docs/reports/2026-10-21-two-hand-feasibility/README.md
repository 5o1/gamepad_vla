# 双手全手柄：阶段 0 可行性与设计（K0）

日期：2026-10-21。范围：固定掌位、指定手指、持续背面握持的仿真几何分析及后续设计。未实现训练，未连接采集台，未执行硬件命令，未改变现有方向键任务或配置数值，未提交 Git。

## 结论摘要

**目前没有得到满足用户规定的“双手全手柄”可行证书，不应据此制作最终固定装置或开始全控件训练。** 每侧搜索 4096 个固定掌位；在背面两指接触点的运动学筛选中，左侧 2487、右侧 2463 个候选成立。即使先忽略碰撞和机械臂，左侧也没有掌位覆盖全部规定控件，右侧同样没有。后续完整碰撞和臂 IK 的结果见下表。

- 完整握持、指定手指、臂IK、碰撞和原生目标接触联合检查后：左侧未找到任何控件通过；右侧只有 Y 键在三个摆放中各有一个静态姿态，并已在另一手保持握持的条件下复核；其他控件本轮未找到通过样本。这不是全局不可达证明，也没有证明 Y 键已能动态按压。
- 现有左拇指方向键技能成立，但它没有持续背面握持约束，不能作为新任务的完整可达性证明。
- 在新握持约束下，摇杆等控件有接触点运动学候选；这和“包住握把后能安全操作”有明确区别。逐控件和组合结果见“可达性结果”。
- 固定方式的建议是：**先评估中部局部支撑、背面握把及扳机完全悬空的可调试验夹具**，以架高 40 mm、保持正面朝上作为首个待验证起点（本轮纯握持候选最多）；不是已经通过的制造方案。还应保留 0°/30°/45°调节和架高 40/70 mm 的对照能力。只改变固定方式不能改变手相对控件的内部运动学，不能承诺消除肩键等瓶颈。
- PPO 没有显示必要性：IK F1=0.94746949，PPO 三种子均值=0.94527468。种子 1、2 的逐时刻数字方向键行为与 IK 完全相同，连续行程和接触力则不同。

**需要用户决定的事项：**

1. 确认右手镜像分工，以及 View/Xbox→左拇指、Menu→右拇指的暂定分配。
2. 是否接受改变实物固定装置；若接受，先选可调中部夹持试验方案，最终高度、角度、夹持位置仍须以通过的完整证书定稿。现有平放装置不能自动迁移。
3. Pair/配对键是资产中额外的物理控件，没有 SDL 核心通道，也未分配手指。是否将其纳入“全手柄”，由哪只手哪根手指操作，是否使用独立事件目标？本次没有擅自分配。
4. 非方向键的电气闭合阈值没有实测；本分析沿用现有任务 0.3 的试验行程比例，是否将它作为后续仿真统一计分阈值，需确认。
5. 本轮有限搜索失败不要求立即放宽左手硬约束。若后续更充分搜索仍失败，是否允许掌位分模式、是否更换手型/加机械传动，必须另行裁决；本次没有采用这些放宽。

## 可达性定义与复现方法

实现：[公共几何模块](../../../src/gamepad_vla/feasibility.py)、[单侧搜索入口](../../../scripts/check_two_hand_feasibility.py)、[配对和间距检查](../../../scripts/check_two_hand_pairs.py)。复用现有 SerialChain 和 `place_gamepad_ik` 的 FK/DLS 思路，独立构建两手两臂碰撞场景；没有修改现有方向键环境。

### 数字键、摇杆、扳机及握持

1. 每根手指随机采样 100000 个独立关节姿态，遵守源 URDF 限位，同时把 mimic 子关节限位反算到源关节。拇指/食指/中指用远端网格的尖端、45°指腹和侧向指腹三个接触点；无名指/小指只用指腹点。
2. 壳体以原始三角形抽取 40000 个表面点。每侧握持区采用控制器局部坐标：左 x<−25 mm / 右 x>25 mm、y<5 mm、z<−5 mm，壳面向下分量 nz<−0.3。只取 `shell` 背面，不以扳机、面板或侧面代替。该区是本次选择的背面采样区域，未覆盖整个可能握持区域。
3. 以无名指指腹接触背面点为锚，采样关节姿态及绕接触法向的旋转，生成每侧 4096 个掌位；小指从附近 24 个壳面点中选初值并做点 IK。左/右随机种子为 21/22。无名指锚定时令两个表面法向相对，这只是候选生成分布，不是额外的角度通过门槛。
4. 对同一掌位，数字键在实际移动至 0.31 行程的表面求接触姿态，法向偏差 ≤30°。十字键用 7 mm 作用半径上的四个点，随真实摇架变换。摇杆检查 0°、45°……315°的 8 个半径 0.8 目标及独立的 L3/R3；8 个方向必须全部通过才计为一个可达摇杆。扳机检查 0.8 行程终点，取可产生正确铰链转矩方向的 3 个表面点作为替代接触点，不把背壳当扳机。
5. FK 点云只作初值：位置/法向最近邻的宽筛选距离为 12 mm，再进行最多 35 次点 IK。最后测量点误差 ≤0.25 mm。数字键才应用 30°门槛，模拟量/握持不附加这个角度拒绝条件。这里没有体素化；0.25 mm 是数值求解分辨率，不是把闭合阈值、80%行程或30°放宽。
6. 对每个固定方式，把同一批相对掌位变换到 world；每条臂作 6 个初值、各 100 次 DLS，限位内位置误差 <0.5 mm、旋转误差 <0.005 rad。臂 IK 随机种子单独固定为左 1021 / 右 1022，复用指尖数组不会改变其初值序列。右侧 mount 采用上述 assumed 对称值。
7. 在独立 MuJoCo 场景检查手与手柄、手/臂与桌面及立柱等箱体、两手、手与对侧臂、臂与臂。G20 和 AR5 使用 URDF 碰撞网格的凸包，手柄使用上游 SDF，octree depth=8；该约 0.6 mm 的名义细分尺度不是有保证的几何误差界。数值接触策略沿用固定资产；参见 [MuJoCo 碰撞计算原始文档](https://mujoco.readthedocs.io/en/stable/computation/index.html#collision-detection)。
8. 无名指/小指实际接触必须由原生碰撞检测发现，最多穿入背壳 1 mm，并在每个被检查的操作姿态中保持同一关节值。指定活动指的distal还必须与目标控件出现原生接触，不能以接近但悬空的指尖计成功。数字目标接触的数值穿透上限为 0.1 mm；非目标碰撞超过 1 μm 即拒绝。这些是公开的几何求解容差，不是实物安全余量。静止的其余三指搜索张开、闭合、10 个确定随机姿态，并补入已求得的操作姿态；每个候选都检查完整网格，不能用一个指尖点代替整只手避碰。

### 必须保留的证据边界

这是**有限采样、静态接触姿态**搜索，不是全局不可达证明。每个普通数字键取一个代表性接触点，扳机取三个替代点；小指只精化一个选中的最近邻初值；可能漏掉其他接触斑、其他局部解和握持区外的解。没有把“点 IK 成功”直接升级为成功按键。

静态构型中的手柄关节位置是构造测试夹具的状态，不是手指已经通过动力学推动到该状态的证据。摇杆接触还需通过摩擦/切向力和连续路径验证；扳机需通过实际拉动与回弹验证。当前结果没有证明这些动作的接触力或 80%动态跟踪能力，也没有证明中间转换路径可行。

保持已有场景的证据边界：同一只手内部和同臂内部自碰撞没有作为新的通过项，连接的同侧手/臂安装接缝不拒绝；两手、对侧臂和臂间碰撞单独检查。单侧统计先把对侧机械臂停在配置 home，对侧手移出工作区；后续把全部已通过握持样本配对，再将两条臂同时放到各自 IK 姿态，因此不能用单侧结果代替双手证书。

架高/倾斜试验先使用理想固定根，**没有把具体夹具网格假装成已经验证的实体支架**。报告的夹具尺寸是设计输入；实体支架加入后可能进一步减少可行候选。因为本轮尚无完整证书，这一缺口不会被隐藏在“推荐固定方式已通过”的表述里。

## 任务与环境设计：仅设计，尚未实现

### 多控件合成目标

生成器先采样“每根活动手指的任务模式”，再采样该模式内的值，避免把同一根拇指指派到两个远隔控件。

- 左拇指模式：neutral / D-pad（含合法相邻对角线）/ LS二维（可和 L3 合并）/ View / Xbox。右拇指模式：neutral / 单个ABXY / RS二维（可和R3合并）/ Menu。ABXY 多键同时按只能在后续取得同指跨键接触证据后增加，不能默认任意组合都可行。
- 食指肩键和中指扳机相互独立，因此允许同侧 LB+LT、RB+RT；这正是本次分工裁决相较食指兼管方案的改变。无名指/小指始终握持，没有随机“松开”模式。
- 拟议采样比例：20% 双手中性，30% 单手单控件，30% 双手同时各一控件，20% 在上述兼容关系内的肩键/扳机/拇指组合。比例只是待实现的起始设计；另设全覆盖均衡评测，不让训练分布掩盖难例。

- 训练、验证、评测种子及轨迹分开；评测至少覆盖每个数字键的按下/保持/释放、摇杆8方位与额外插值方位、L3/R3、扳机分级及合法跨手组合。非法同指组合单列为“目标不可执行”，不能混入可执行集后归咎策略，也不能悄悄删除合法难例。

### 奖励：从方向键到模拟跟随

参考 [RoboPianist 论文](https://arxiv.org/abs/2304.04150) 和[官方奖励实现](https://github.com/google-research/robopianist/blob/main/robopianist/suite/tasks/piano_with_shadow_hands.py)：采用正确键、误键、指尖接近和能耗的分项思想；不复制钢琴的 MIDI 数据、前瞻或手型。当前方向键的“正确闭合且无误按”、指尖距离、能耗、动作变化和接触力结构保留为出发点。

拟议结构：

```text
r = w_d * mean(数字目标保持奖励，闭合裕量以上不再奖励额外下压)
  + w_a * mean(g(每个模拟控件的归一化跟随误差))
  + w_tip * mean(当前指定指尖到当前作用点的接近奖励)
  + w_grip * mean(四个固定握持指腹的接触保持奖励)
  - w_wrong * 非目标数字键/非目标模拟位移
  - w_E * sum(abs(tau * qdot)) * dt
  - w_delta * sum((a_t - a_(t-1))**2)
  - w_F * 过大接触力与穿透
```

对摇杆使用二维向量距离和径向/切向误差，扳机使用归一化绝对误差；通过函数 g 把误差映射到 [0,1]。不要只奖励模拟量“超过0.8”，否则策略会一直顶满而不能跟随中间值。数字/模拟两类先分别按有效控件数量归一化，再加权，避免 4 个十字键通道压过一个二维摇杆或全中性目标刷分。权重、模拟容差及力阈值待小规模 IK 接触实验后确定，本任务没有把任何候选值写入环境。

持续握持和非目标碰撞是可行性约束，单独记录失效时间和终止原因；不能只用一个奖励项允许策略拿其他分数补偿松手。发生失效后的目标仍计失败，不能从 F1 分母里剔除。动作切换和 40–60 ms 响应期仍参与逐步评测。

### 评测与连续 IK 先验

| 指标 | 统计口径 |
|---|---|
| 数字控件 | 每控件 TP/FP/FN/F1，宏平均和微平均；中性段误触率；同时组合完整状态准确率 |
| 摇杆/扳机 | 全时段归一化 MAE、RMSE、P95、峰值，摇杆向量/半径/方向误差；中性漂移和跨控件串扰 |
| 延迟 | 阶跃响应中位/P95，未响应事件数；按下与释放分开；模拟量另报到达目标带的稳定时间 |
| 接触 | 每指/每控件接触力峰值和P95、冲量、穿透、握持失联比例与最长失联；非目标手/臂碰撞次数 |
| 固定掌位证书 | 各控件的作用姿态、8方位与80%行程、数字30°、固定握持q、两臂IK、两手/两臂间距；全部门槛沿用户定义 |
| 计算与真实范围 | 控制步数、模拟秒数、墙钟时间、有效轨迹分母；静态、动态、游戏闭环和硬件分别报告 |

连续 IK 先验从离散姿态族推广为：在摇杆二维目标网格及 L3 状态建立同一掌位的接触姿态库，按当前目标插值为初值，再以实际位姿/法向及碰撞约束精化；扳机沿铰链曲线建立同样的连续作用点。相邻参考用共享锚点和最小关节变化选支，避免 IK 解支跳变。只查询当前目标；释放/换控件时使用测得的接触状态执行抬起/绕行，不偷看后续目标。单纯关节线性插值没有自动避碰或保持握持保证，须用原始判据逐段复核。

### PPO 是否必要：最小对照

K0 不训练。下一阶段首先运行 IK+相同 PD/反馈基线，直到有动态接触证据；若基线已经满足任务目标，PPO 不作为必经阶段。

最小的学习增益判别为三臂配对：A=相同 IK/反馈控制器、残差严格为零；B=同一先验+训练所得残差；C=与B幅度匹配、打乱时间的残差，区分学到的校正和任意扰动。先用已有方向键模型做零残差/模型残差回放检查，再在新增的第一个可执行技能上使用 3 个训练种子、每种子 16384 步和完全相同的评测轨迹。所有控制增益、动作界、准备段、目标时序、接触参数保持一致。

在标称条件和一组明确的合成扰动条件分别配对评测；如±1 mm摆放误差、回弹刚度±20%仅代表敏感性试验，不冒充实物不确定性分布。统计每条轨迹的差值和按轨迹重采样的置信区间。只有B相对A在数字F1或模拟误差上有可重复改善，且误触、握持和力指标不恶化，并优于C，才支持保留PPO；若输出仍相同或只有力变大，就不把“有非零动作”“奖励变高”当收益。3×16384不是保证收敛的预算，只是判断是否值得增加预算的首个门槛。
