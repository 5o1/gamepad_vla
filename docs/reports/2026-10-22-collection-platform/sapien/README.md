# SAPIEN 双手双臂采集适配器

日期：2026-10-22。此页只记录 SAPIEN 负责人实际完成的实现与 CPU 短测。L1、L2 和推流门槛由总报告记录；本页的一秒短测不构成它们通过的证据。

## 实现

新增 `src/gamepad_vla/workstation/collection_sapien.py`，不修改原 SAPIEN 后端或方向键任务。场景读取 v4.4 的桌面、固定碰撞装置、手柄根固定方式、双 AR5 与两侧独立手部资产。右手使用配置指定的右手 URDF；不把左手网格镜像冒充右手。安装偏移数值沿用 v4.4 的对称设计，其物理确认状态应在共享场景元数据中标为 `assumed`。没有采用双手可行性报告建议的新夹具；该报告也没有给出现有装置满足全控件握持约束的证书。

两侧 `HandCommand` 和 `ArmCommand` 均只改变驱动目标。初始化及 `reset()` 设置初态，此后每步通过 CPU PhysX 计算真实状态。手部软件 mimic 分别使用左侧拇指 1.02、右侧拇指 1.03，四指 0.89；观测记录模拟器实际求解后的全部 21 维角度，不把 mimic 目标当成实测值。每侧自碰撞关闭，左右两侧之间及机器人与环境之间保留碰撞。

输出使用共享 schema v2，手柄信号调用用户手柄仓库的 `gamepad_state()`，控件行程调用 `joint_positions()`。没有设置请求手柄信号来伪造物理反馈。`robot_contact` 由共享 `workstation/contact.py` 判断，表示上一个控制间隔内任意物理子步的机器人接触点存在 `separation<=0`，与 MuJoCo 的几何距离 `dist<=0` 对齐；不把正间隙的 contact-offset 候选算成接触，也不是只检查最后一个子步。掌根和指尖采用共享世界坐标系、米、弧度及 `[x,y,z,qw,qx,qy,qz]` 定义。指尖偏移由共享工具读取每侧 distal 碰撞网格的局部 +Z 极值，具体数值保存在 [smoke.json](smoke.json)。

物理步长为 1 ms，时间由累计物理 tick 给出。`step(dt)` 累积请求时间，执行不超过它的完整物理步，保留不足一个步长的余量；不会每次独立四舍五入，也不会把请求时间伪写成实际仿真时间。50 Hz 时每步恰好 20 个子步；30 Hz 时实际采样时间最多落后请求时间不足 1 ms。

默认构造 `sapien.Scene([sapien.physx.PhysxCpuSystem()])`，不创建 `RenderSystem`。在传给 URDF loader 之前，从派生文件中移除 `visual` 和 `material`，保留碰撞、惯性、关节及网格尺度；用户手柄仍经过其公共加载接口与原 SDF 设置。其原因是 SAPIEN 3.0.3 的默认 `Scene()` 会自动构造渲染系统，URDF 解析也可能创建渲染材质。依据为实际环境中的 SAPIEN 3.0.3 `wrapper/scene.py` 与 `wrapper/urdf_loader.py`，对应 [SAPIEN 3.0.3 源码](https://github.com/haosulab/SAPIEN/tree/3.0.3/python/py_package/wrapper)。该适配仅派生本次运行文件，不修改资产源文件或用户手柄仓库。

显式 `render=True` 提供独立渲染副本。`set_render_state()` 只接受物理进程产生的实际角度与控件行程，不推进物理；`render_rgb()` 输出 640×480 RGB。GPU 全忙，本轮没有执行这个分支，不能据此声称达到 30 fps。

## 实际短测

采用独立代码副本、已有 SAPIEN 3.0.3 环境与手柄 0.3.1 资源。运行前查询 GPU，四张卡均忙；全部运行设置 `CUDA_VISIBLE_DEVICES=''`。没有安装依赖或连接采集台。

入口为 [smoke.py](smoke.py)，结果为 [smoke.json](smoke.json)。测试从 v4.4 初态开始，两侧拇指 MCP 同时增加 0.03 rad，两侧机械臂第七轴同时增加 0.02 rad，执行 50 次 20 ms 控制步并逐次验证共享 Observation。

| 项目 | 实际结果 |
|---|---:|
| 加载墙钟时间 | 3.206 s |
| 驱动及观测墙钟时间 | 0.651 s |
| 实际仿真时间 | 1.000 s |
| 控制观测次数 | 50 |
| 渲染组件数 | 0 |
| 有机器人接触的控制间隔 | 0/50 |
| 左/右拇指 MCP 实际增量 | 0.02999845 / 0.02999213 rad |
| 左/右机械臂第七轴实际增量 | 0.01998386 / 0.01999855 rad |
| 状态有限性与 schema 验证 | 全部通过 |

约 76.9 次控制观测/墙钟秒仅表示此无接触、无图像的一秒短测吞吐，不是视频帧率，也不能外推五分钟接触回放。

## 用户裁决 2：自由空间变体

按用户后续裁决，新增构造参数 `environment_collisions=True`，默认完整场景保持原行为；传入 `False` 时由代码生成 `no_environment_collisions` 变体，v4.4 文件不变。桌面、立柱及其他固定物不创建碰撞形状；手柄仍通过原公共接口加载，所有碰撞形状的 membership/affinity 即 `groups[0:2]` 清零，保留手柄内部原来的过滤保留字。机器人模型、关节限位、安装、重力补偿、驱动、自碰撞设置及两侧之间的碰撞均不改变。共享录制层将变体写入元数据。

同一 [smoke.py](smoke.py) 加 `--no-environment-collisions`，先只加载默认场景取得机器人碰撞签名，随后对变体执行一秒真实驱动短测；没有重新运行完整模式的 60 秒回放。结果为 [smoke_no_environment_collisions.json](smoke_no_environment_collisions.json)：

| 项目 | 实际结果 |
|---|---:|
| 变体加载墙钟时间，同进程资源已预热 | 0.510 s |
| 驱动及观测墙钟时间 | 0.588 s |
| 实际仿真时间 / 控制步数 | 1.000 s / 50 |
| 左 / 右机器人碰撞形状数 | 31 / 31 |
| 逐链接碰撞形状数量和过滤组与默认场景一致 | 是 |
| 固定环境碰撞形状数 | 0 |
| 手柄接触过滤字 | 每个形状 `[0,0,2147483648,22594]` |
| `robot_contact` | 0/50 |
| 渲染组件 | 0 |
| schema 与有限性 | 通过 |

这是变体的短测，L1/L2 数值仍以主代理统一运行结果为准，没有擅自缩短其时长或放宽门槛。

## 修复记录

每步最多三次修复，未改变门槛。

| 步骤 | 修复次数 | 失败与处理 | 后续结果 |
|---|---:|---|---|
| 首次观测 | 1/3，共享模块由主代理修复 | `tip_pose()` 将 ndarray 交给只接受 list/tuple 的 `pose_to_matrix()`；改用 `pose.tolist()` | 原始失败日志保留；第二次短测通过 |
| 重置兼容与渲染快照接口 | 0/3 | 捕获用户手柄加载初态作为 reset 来源，兼容尚无新 ResetRequest 接口的已安装资源版本；新增实际状态渲染接口 | 修改后 CPU 短测再次通过；渲染分支未运行 |
| 跨后端接触定义 | 1/3 | 原先只检查 `contact.points` 非空，会把 PhysX 正间隙候选算成接触；依据已安装 API 与真实接触点改用 `separation<=0`，不更改物理 | 原八月数据首 0.1 s 重验与几何判据完全一致，三个控制间隔仍均有真实接触 |
| 用户裁决 2 的自由空间变体 | 0/3 | 由构造开关关闭固定环境与手柄碰撞，接触判据迁到共享 helper | 第一次一秒 CPU 短测通过，机器人碰撞签名不变；未自行运行 L1/L2 |

本负责人没有执行 L1/L2，也没有生成诊断图；统一门槛结果见总报告。原始日志留在计算工作目录，公开结果移除了机器地址、账号和站点路径。

接触定义诊断使用 [contact_diagnostic.py](contact_diagnostic.py)，逐物理子步汇总原八月回放首 0.1 s，结果见 [contact_diagnostic.json](contact_diagnostic.json)。24 个机器人碰撞对中既有正间隙零冲量候选，例如臂 link6 与桌面最小间隙 14.917 mm，也有真实穿透：左摇杆与左拇指 distal 最小 −3.578 mm、左拇指 distal 与桌面 −0.601 mm、左小指 distal 与桌面 −0.438 mm。三个 30 Hz 控制间隔在修复前后都为有接触，因此不能把首段接触全部归因于候选点误判。正间隙也可能出现预测求解冲量，例如掌根与手柄最小间隙 +0.308 mm 时仍有非零冲量；这里仍只以几何符号分类，与 MuJoCo 保持同义。该最小诊断没有改变场景、姿态或驱动参数，也没有重录 L1。

## 我自行做出的未授权选择

- 沿用已有 SAPIEN 基线的占位 PD：手部 Kp=240、Kd=8、力矩上限 60、armature=1e−4；臂 Kp=20000、Kd=2000、力矩上限 500、armature=1e−2。每子步补偿重力和科氏/离心项。数值没有实测辨识；没有宣称适用于硬件。
- 新采集后端采用 1 ms 步长，并采用不足一步时保留时间余量的策略。主代理已确认这项实现选择；旧任务参数不变。
- 为独立渲染副本提供一个围绕手柄的临时观察视角。它不是标定相机，当前没有验证图像外观或帧率。

上述选择没有改变采集台或固定装置，没有引入训练、BC 或 DAgger。
